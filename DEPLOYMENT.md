## Post-deploy steps for the client

The client (`0xFE968dE21eb0E77d5877477C31a04A3075c0086E`) is the `Ownable2Step` owner of the contract. Reminders:

1. **Set the CV token (one-shot, optional).** `cvToken` deployed as `address(0)`. When/if a real ERC-20 CV token exists, the owner can wire it in by calling `setCvToken(address newCvToken)` exactly once. After that call, `cvToken` becomes immutable. The contract has no setter to change it again — design choice from Stage 4.
2. **Ownership transfer is two-step.** `Ownable2Step` is in use. To transfer ownership to a new wallet:
   - Current owner calls `transferOwnership(newOwner)`.
   - The new owner must then call `acceptOwnership()` from the `newOwner` address.
   - Until `acceptOwnership` is called, the old owner remains in control. Do not assume ownership has moved after step 1 alone.
3. **Worker wallet has no privileges.** The deployer wallet `0x5430757...A779200` paid gas only. It has no role, no allowance, and no ownership in this contract. There is no need (or way) to revoke anything from it.
4. **Frontend wiring.** `packages/nextjs/contracts/deployedContracts.ts` was auto-generated by `yarn deploy` and committed alongside this file. Stage 6 will hook the UI to this address.

## Reproducibility

Deployed from commit pre-`DEPLOYMENT.md` HEAD with:

```bash
export OWNER=0xFE968dE21eb0E77d5877477C31a04A3075c0086E
export CLAWD_TOKEN=0x9f86dB9fc6f7c9408e8Fda3Ff8ce4e78ac7a6b07
# CV_TOKEN intentionally unset

cd packages/foundry
forge script script/Deploy.s.sol \
  --rpc-url base \
  --broadcast \
  --ffi \
  --private-key "$PRIVATE_KEY"
```

`base` RPC is the Alchemy endpoint configured in `packages/foundry/foundry.toml` under `[rpc_endpoints]`.
